# v0.44.0

This release reads packs written to the specification's released `specVersion` `0.5.0`, which
carries annotations and value sets, and removes the unreleased working selector `0.4.0-draft`
that `v0.43.0` read experimentally.

## Changes for hosts upgrading from `v0.43.0`

- **Nothing changes for a pack under `0.3.0`, `0.2.0-draft` or `0.1.0-draft`**, with the three
  small exceptions listed under "Other changes". `0.3.0` stays the default selector.
- **A pack that declares `0.4.0-draft` is no longer read.** The specification released that text
  as `0.5.0` (Spec `v0.5.0`), and the working selector was never a released one. Such a pack is
  refused with `JPS-CAPABILITY-SPEC-VERSION` and a note that says where the draft went. Move the
  pack by changing its `specVersion` to `"0.5.0"`; its bytes and so its digest change. Upgrade
  the runtime and the packs together: `v0.43.0` does not read `0.5.0`.
- **`0.5.0` refuses some packs the draft admitted.** After the move, a pack must also meet the
  released rules:
  - An annotation string holds no direction-changing character, no invisible or
    default-ignorable character, and no white space at either end. (`v0.43.0` admitted
    direction marks and isolates, zero-width characters and variation selectors.)
  - A local identifier, an extension name, a pack version and a decimal operand hold no line
    break.
- **Experimental members that only the draft used are removed or renamed.**
  - Removed: `sdk.Evaluator.Stage`; the `stage` member of the runtime description's evaluator
    entries; the `suiteStatus` member, the `held` count and the `held` case status of a
    conformance or corpus run; the `suite staged` label and `held:` lines in human output; the
    code `JPS-SUITE-STAGED`.
  - Renamed: the code `JPS-STAGED-DRAFT-UNSUPPORTED` is now
    `JPS-SURFACE-SPEC-VERSION-UNSUPPORTED`.
  - A specification lock that states a `stage` is refused at load.
- **Runtime discovery lists `0.5.0` in place of `0.4.0-draft`.**

## What `0.5.0` adds to a pack

A pack that declares `"specVersion": "0.5.0"` may carry:

- **Annotations.** Under the reserved extension `org.judgmentpack.annotations`, on the pack, an
  outcome, a rule and a value-set entry: 1 to 16 keys, each value a string or a list of strings.
  Annotations never change a decision.
- **Value sets.** A root `valueSets` member holds named sets of values. A fact `in` condition
  names one with `valueSet` in place of an inline `value` list, and is evaluated exactly as if it
  listed the set's values. A reference to a set the pack does not define is refused
  (`JPS-SEMANTIC-UNRESOLVED-VALUE-SET`).

The pack's identity and digest stay over the exact bytes loaded. The bundle is vendored from
Spec `v0.5.0`, commit `171d4c21d4b13e03ee20e1adb6fc5cc6b182cfae`. Only the `base` profile is
read; the `extended` profile's cases are reported as skipped. This runtime makes no conformance
claim for `0.5.0`: [CONFORMANCE.md](../../CONFORMANCE.md) records the results of its runs as
preparation evidence, and the claim stays as that file states it.

## Where `0.5.0` is read, and where it is refused

- **Read:** validation, `spec test-conformance --spec-version 0.5.0`, the evaluator,
  `experimental evaluate-corpus`, `compare`, the project walk and coverage, fact advice, matrix
  validation, the examples, the pack description and its filter, and the MCP tools that reach
  them. The MCP standalone `spec_version` accepts `0.5.0`.
- **Refused:** every graph command that reads node packs (`experimental graph validate`,
  `explain`, `test` and `evaluate`, and the MCP graph test tool), the dialect check and the
  policy check refuse a `0.5.0` pack with `JPS-SURFACE-SPEC-VERSION-UNSUPPORTED` (exit 2) and
  name the versions they read. Pack-design analysis reports `pack-unsupported`. The documents
  these surfaces implement are written against Core `0.3.0`.

## Describing and filtering

`jpack packs describe`, `--filter key=value`, `sdk.Pack.View` and `sdk.Pack.FilteredView` work
for a `0.5.0` pack as `v0.43.0` documented them for the draft. Two things change in the
Markdown form; the JSON form is unchanged and `viewVersion` and `filteredViewVersion` stay
`"1"`.

- **Text cannot reorder its line** (ADR-0078). An annotation key or string, or a filter
  criterion, that holds a right-to-left or Arabic-number character, or that begins with a
  combining mark, is written only in its ASCII form, `` (ASCII only `"..."`) ``. Read the exact
  characters from the JSON form.
- **A run of spaces stays visible.** Text with two adjacent spaces is followed by its ASCII
  form, with each space of the run written ` `.
- A filter criterion that the display rules refuse is refused as a criterion (ADR-0076).

## Other changes

- `packs describe --filter` checks a criterion before the pack's selector, so a criterion the
  rules refuse is reported as a criterion on a pack under any selector. The selector refusal now
  names `0.5.0`.
- The `label` of an `experimental evaluate-corpus` run, and the first line of its human report,
  now say when the run's `specVersion` is outside the version scope of the claim in
  CONFORMANCE.md. This changes the label of a `0.3.0` run. Results are unchanged.
- `spec test-conformance` skips a case only for a profile that the suite defines and this
  runtime does not read.
