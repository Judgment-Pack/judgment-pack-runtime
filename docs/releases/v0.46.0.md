# v0.46.0

This release adds a structural comparison of two pack versions, a decision record whose facts
are named by digests the caller keys, a severity check in `packs validate`, pack-design analysis
of Core `0.5.0` packs, a check that a published pack or dialect keeps its bytes, and a way to
re-validate a project's matrix results before a Runtime pin moves.

## For an unchanged pack

For every supported `specVersion` (`0.5.0`, `0.3.0`, `0.2.0-draft`): no disposition, no
evaluation output, no decision record byte and no digest differs from `v0.45.0`. The release
review compared the two releases over the Spec's corpus (626 packs through `spec validate`, 540
decision records over the three corpora, the conformance run with and without `--strict`, and
`packs test` output), and `experimental revalidate` reads a `v0.45.0` `packs test` report as its
baseline. The exceptions are in what is reported about a pack, not in what it decides:

1. **Every pack view states `viewVersion` `"2"`** (`packs describe` in JSON and Markdown, and the
   Go view). For a `0.3.0` or `0.2.0-draft` pack that line is the only change. A `0.5.0` view
   gains a `severity` member beside `pack` and a Severity column. A consumer that accepts only
   `viewVersion` `"1"` refuses every view until it is updated.
2. **`packs validate` gains a seventh check**, `annotation-vocabulary`, and a `vocabulary` member
   on each pack entry; the human output gains one line per pack.
3. **A Core `0.5.0` pack can now fail `packs validate`** (exit 1): when an outcome's `severity`
   annotation is not exactly `low`, `medium`, `high` or `critical`, or is a list. There is no
   option that turns the check off; a project that uses another scale under that key renames
   its key. The vocabulary itself is `proposed` in Spec `v0.5.2`. Packs under other selectors
   are not checked.
4. **With `--fail-on-advisory`**, a `0.5.0` outcome whose identifier ends in a level other than
   its stated severity fails the pack.
5. **`experimental analyze-pack`** (CLI and MCP) analyses a base-profile `0.5.0` pack, which it
   refused before (exit 1 then, a report and exit 0 now). Its refusals of `0.5.0` packs carry a
   longer message, and the MCP tool's description changed.
6. **The graph commands and tools and the policy check** add one sentence when they refuse a
   `0.5.0` pack; the code and the exit are unchanged.
7. **Go API**: `view.ViewVersion` is `"2"`; exported struct fields were added (the record's keyed
   digests, the view's severity). Nothing exported was removed or retyped; only unkeyed composite
   literals of those structs stop compiling.

Help text changed for `packs validate`, `--fail-on-advisory`, `packs describe`, `compare` and
`analyze-pack`.

## What is new

- **`packs diff`** (ADR-0086; EXPERIMENTAL) compares two pack documents member by member,
  annotations included, or two with their common base (`--base`). It evaluates nothing; a
  threshold that moved is reported whether or not any input falls between the two values.
  `sdk.Diff` and `sdk.ThreeWayDiff` return the same comparison, and `experimental compare
  --structural` adds it to compare's output.
- **A decision record with keyed digests** (ADR-0087; EXPERIMENTAL).
  `Pack.EvaluateWithKeyedRecord` writes a record (`recordVersion` `"2.0.0"`) whose facts and
  evidence are named by HMAC-SHA-256 digests the caller computes with its own key; the Runtime
  never receives the key. A holder of the key can check a document against the record after the
  document is gone from everywhere else; a reader without the key cannot test candidate
  documents against it. The disposition stays readable. `record.Read` and `CheckDocuments` read
  both forms, and `record.CanonicalFacts` and `record.CanonicalEvidence` give the text the
  digests are taken over. Keep a key for these digests only.
- **Severity in `packs validate` and the view** (ADR-0088). See exceptions 1 to 4 above;
  `sdk.Pack.CheckVocabulary` returns the same check.
- **Pack-design analysis of Core `0.5.0` packs** (ADR-0089; EXPERIMENTAL).
- **`experimental check-published`** (ADR-0090; EXPERIMENTAL) reads a git repository's tags and
  reports every pack or dialect identity (kind, id, version) whose bytes at a later tag or at
  HEAD are not the bytes first published, optionally against a manifest of pinned digests. It
  runs `git` from `PATH` and writes nothing into the repository. Known limits, to be fixed in
  the next release: run time grows quickly when very many documents share one identity, and
  memory is not bounded for documents with very long ids or versions.
- **`experimental revalidate`** (ADR-0091; EXPERIMENTAL) writes a baseline of a project's matrix
  results under the pinned Runtime and compares it under a candidate. It also reads a `packs
  test --format json` report as the baseline, so the move from `v0.45.0` can be checked with
  the report `v0.45.0` already writes. The procedure and a CI recipe are in
  [docs/revalidating-a-runtime-pin.md](../revalidating-a-runtime-pin.md).

## Compatibility

| With | Version | Notes |
|---|---|---|
| Specification | Spec `v0.5.0` to `v0.5.2` (Core `0.5.0`, `0.3.0`, `0.2.0-draft`, `0.1.0-draft`) | Core is unchanged since `v0.5.0`. `0.3.0` stays the default selector. Only the `base` profile of `0.5.0` is read. The severity vocabulary `1.0.0` is the one in Spec `v0.5.2`. |
| Dialect documents | format version `3` | The proposed dialect format `4.0.0` is not read by this release. |
| Decision records | `recordVersion` `1.0.0` (plain) and `2.0.0` (keyed) | The plain form's bytes are those `v0.45.0` writes. |
| Runner | `v0.31.0` and later | The Runner states the Runtime it was released against in its own notes. Nothing in this release changes what a Runner reads from the Runtime. |
| Gateway | any | The Runtime does not call the gateway. |
| Audit trails and lock files | written by any earlier release | Read unchanged. |

ADR-0087 to ADR-0091 are accepted with this release (ADR-0086 was accepted on merge).
