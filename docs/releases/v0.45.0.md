# v0.45.0

This release adds ways to make a pack's tests a gate, to sign a pack file, to get a decision
record from the Go API, and to evaluate many facts documents in one run. Nothing changes for an
existing command line, pack, lock file or audit trail.

## Changes for hosts upgrading from `v0.44.0`

- **No pack, lock file, trail or existing command changes.** Every addition is a new option, a
  new command, a new member in JSON output, or a new package. The conformance claim in
  [CONFORMANCE.md](../../CONFORMANCE.md) is unchanged.
- **`packs validate` JSON gains members**: `advisories`, `advisoriesTruncated` and, with the new
  option, `failOnAdvisory`. A reader that refuses unknown members must be updated.
- **`packs test` JSON gains members** when the new options are used: `minCoverage`,
  `requireBoundaries`, `unmetRequirements`, and the test-strength report.
- **Faster loads.** The configuration schema is compiled once per process and each bundled
  specification is checked once per process. Both are held by their embedded bytes; nothing read
  from disk is skipped.

## What is new

- **Tests as a gate** (ADR-0080). `packs test --min-coverage N` and `--require-boundaries` fail a
  run whose matrix does not reach the stated coverage or does not witness each boundary
  (`JPS-INVOCATION-MIN-COVERAGE` for a bad option value).
- **Overlap advice in `packs validate`** (ADR-0081), with `--fail-on-advisory` to fail on it.
- **Test strength** (ADR-0084; EXPERIMENTAL). `packs test --strength` derives weakened variants
  of each pack in memory, runs the pack's own matrix against each, and reports each variant as
  noticed, survived or not derivable. `--fail-on-survivor` makes it a gate; `--max-variants`
  bounds the work. A survivor is a gap in the matrix or a change that makes no difference; no
  survivors is not a statement that the pack is right.
- **Pack signing** (ADR-0083; EXPERIMENTAL). `packs sign` writes a detached Ed25519 signature
  over the pack file's bytes beside the pack (`<pack>.sig.json`); `packs verify-signature` and
  the package `sdk/packsig` check it against a key the reader names. A signature is not part of
  the pack, its digest, a lock file or the audit trail.
- **A decision record from the Go API** (ADR-0079; EXPERIMENTAL). `Pack.EvaluateWithRecord`
  returns the decision with a canonical record (package `sdk/record`, `recordVersion` `1.0.0`)
  that holds digests of the facts and evidence. It is written nowhere.
- **Batch evaluation** (ADR-0085; EXPERIMENTAL). `experimental evaluate --batch <file|->
  --format json` reads JSON Lines, one facts document per line, and answers one line per item in
  input order with the bytes and exit code a single run gives. With the audit trail on, each
  decision keeps its own record, appended in chunks under one hold of the trail's lock. The
  output is a lower bound on what was recorded: read the changelog entry before re-running a
  batch that stopped.
- **`dialect check` reads Core `0.5.0` packs** (ADR-0082).

## Compatibility

| With | Version | Notes |
|---|---|---|
| Specification | Spec `v0.5.0` and `v0.5.1` (Core `0.5.0`, `0.3.0`, `0.2.0-draft`, `0.1.0-draft`) | `v0.5.1` leaves Core unchanged. `0.3.0` stays the default selector. Only the `base` profile of `0.5.0` is read. |
| Dialect documents | format version `3` | The proposed dialect format `4.0.0` in Spec `v0.5.1` is not read by this release. |
| Runner | `v0.30.0` and later | The Runner states the Runtime it was released against in its own notes. Nothing in this release changes what a Runner reads from the Runtime. |
| Gateway | any | The Runtime does not call the gateway. |
| Audit trails and lock files | written by any earlier release | Read unchanged. A trail written by a batch is read by `v0.44.0`. |

## Decisions

ADR-0079 to ADR-0085 are accepted with this release.
