# v0.50.0

This is the registry line's last release before it is named stable. An interrupted emitter run
now has a code of its own. The conformance harness leaves out an untracked link that leads out of
the repository, such as a virtual environment's interpreter, instead of refusing the run. The
shared JSON decoder and canonical form cost less and give the same bytes. The release also
records the line's support policy, which takes effect from the release that names the line stable.

## For an unchanged pack

For every supported `specVersion` (`0.5.0`, `0.3.0`, `0.2.0-draft`, `0.1.0-draft`), no
disposition, evaluation output, decision record byte or digest differs from `v0.49.0`. Comparing
the `v0.49.0` release binary with this release's build:

- **Conformance runs.** For each selector, with and without `--strict`, `spec test-conformance
  --format json` gave the same bytes and the same exit code, apart from the tool's version.
- **The evaluation corpora.** For `0.2.0-draft`, `0.3.0` and `0.5.0` (20, 20 and 103 cases),
  `experimental evaluate-corpus --format json` gave the same bytes apart from the tool's version.
- **Spec validation.** On each of the 2709 JSON documents of Spec `v0.6.0`, `spec validate` gave
  the same exit code and the same output.

The new JSON reader is where a byte change would come from. Besides this comparison, its tests
compare it with the old decoder over every JSON document in the repository, random and damaged
documents, and a fuzz target. The release review also built v0.49.0's decoder beside the new one
and compared them over 400,000 documents at many bounds, finding no difference.

## What is new

- **`EMIT-INTERRUPTED`** (ADR-0098, provisional).
  - `jpack emit` interrupted before its write, or while its emitter runs, is refused with this
    code, once, at `/command`. No later environment's emitter is started.
  - `jpack emit conformance` interrupted reports it too.
  - What ended the emitter decides, read from its wait status and from what first ended the run.
    An emitter that exited non-zero or ran out of time is still `EMIT-PROCESS`, and one that
    exited 0 before the interrupt keeps its response.
- **`jpack emit conformance --update` gates its write** (ADR-0099).
  - An interrupt before a vector's `expected/` is replaced refuses the run at that vector and
    leaves `expected/` untouched.
  - Once the replacement has begun, it finishes, so `expected/` is never left missing.
- **Untracked outward links** (ADR-0099). The harness reads the repository's git index itself,
  versions 2 to 4, and never runs git. It leaves an outward symbolic link or junction out of the
  repository copy, and names it with the new provisional warning `EMIT-LINK-OMITTED`, when all
  three hold:
  - git does not track it or anything below it;
  - no owns glob could match it;
  - the vectors directory does not meet it.

  Every other outward link is refused as before.
- **Every outward link is still refused** when:
  - `--root` has no `.git` directory, or `.git` is a file (a linked worktree);
  - git may read another index or working tree: `GIT_INDEX_FILE`, `GIT_DIR` or `GIT_WORK_TREE` is
    set, `.git/config` mentions `worktree` or `include`, or `.git/config.worktree` exists;
  - the index is missing (a repository with nothing added yet), or fails its checksum. That
    includes an index written with `index.skipHash`, which `feature.manyFiles` turns on;
  - the index is a split or sparse index, past its size bounds, or holds a form the reader does
    not read.
- **Cost** (#464).
  - Valid JSON is now read by a hand-written reader, with the standard decoder kept for a document
    that is not valid JSON.
  - Object members are ordered by UTF-16 code units in place, and a bounded canonical form is
    built in one pass.
  - Decoding allocates 2.3 to 3.8 times less and takes 3.6 to 6.1 times less time.
  - Every decoded value, canonical form, digest, diagnostic code, location and message is
    unchanged. The old decoder and member order are kept in the tests and compared with the new.
- **Descriptors.** Where `/dev/fd` lists only 0 to 2, every number from 3 up to the hard
  descriptor limit, at most 65536, is marked close-on-exec before the first emitter starts.
- **The registry line's support policy** (VERSIONING.md).
  - Security fixes may refuse input that was accepted before. So may conformance fixes, when the
    released companion text forbids that input.
  - Fixes land in the latest minor release. Security fixes are also backported to the previous
    minor for three months.
  - All of this takes effect from the release that names the line stable. That release has not
    happened, so every registry-line code stays provisional.

## Changes a caller may notice

- **Interrupt codes.** `jpack emit conformance` interrupted reports `EMIT-INTERRUPTED`, where
  v0.49.0 reported `EMIT-HARNESS-BOUND`. `jpack emit` interrupted reports `EMIT-INTERRUPTED`, where
  it reported `EMIT-PROCESS`.
- **Outward links.** A repository that held an untracked outward link, which v0.49.0 refused with
  `EMIT-HARNESS-BOUND`, now runs and warns `EMIT-LINK-OMITTED`. With several outward links, the
  refused path named can differ from v0.49.0's.
- **The `expected/` walk.**
  - A listing more than one past the 10000-file bound is refused at `expected/`, where v0.49.0
    refused it at file 10001.
  - `--update` refuses, rather than replaces, an `expected/` of more than 256 directories that
    holds no file.
  - A record of 9999 or 10000 files that also holds empty directories is now `EMIT-VECTOR`, where
    v0.49.0 read it.

## Known limits

- **An index with an offset table.** The index reader passes over the `IEOT` and `EOIE`
  extensions and reads entries in order. A hand-made index whose offset table disagrees with its
  entries can be read differently by git with several index threads, and a link git tracks can
  then be left out with `EMIT-LINK-OMITTED`. The copy still never holds an outward link. This is
  #475.
- **Interrupt outcomes.** An interrupt during `jpack emit --check`'s compare is not reported, and
  the run exits 0 or 1. An interrupt during `jpack emit`'s write reports the files written, with
  exit 0. An interrupt that ends a group member's response on the last environment, after the
  leader exited 0, can give `EMIT-RESPONSE`. This is #475.
- **An emitter that leaves its process group.** When the interrupt cannot reach it through its
  group, the run is reported `EMIT-PROCESS`, still a failure.
- **On Windows,** an interrupt at kill time may report `EMIT-INTERRUPTED` for an emitter that was
  already failing with exit 1.
- **Descriptors.** A descriptor above the scan's top is still missed. That is one opened before
  the hard limit was lowered below it, or one above 65536 where the hard limit is higher.

## Compatibility

| With | Version | Notes |
|---|---|---|
| Specification | Spec `v0.5.0` to `v0.6.0` (Core `0.5.0`, `0.3.0`, `0.2.0-draft`, `0.1.0-draft`) | Core `0.6.0` is not read by this release. `0.3.0` stays the default selector. Only the `base` profile of `0.5.0` is read. |
| Registries and emitters | spec RFCs 0034 to 0037; the registry companion's v0.7.0 draft | The registry companion is not yet released, so its codes are provisional. Emit request and report version `1.0.0`; harness report version `1.0.0`. |

| Start-up module | `startup/v0.1.0` | Tagged on its own. The start-up changes on the main branch since that tag ship with `startup/v1.0.0`, which the release that names the registry line stable tags. |

| Dialect documents | format version `3` | Unchanged from `v0.49.0`. |
| Decision records | `recordVersion` `1.0.0` (plain) and `2.0.0` (keyed) | Unchanged from `v0.49.0`. |
| Runner | `v0.31.0` and later | Nothing in this release changes what a Runner reads from the Runtime. |
| Gateway | any | The Runtime does not call the gateway. |
| Audit trails and lock files | written by any earlier release | Read unchanged. |

## Decisions

No ADR changes status in this release. ADR-0098 and ADR-0099 are amended in place.

The release review ran as one clean room over the whole diff (same vendor, not a cross-vendor
claim). It found no HIGH and no MEDIUM. Its low-severity findings are the first two known limits
above, carried in #475 for v0.51.0. The Go facts builder's any-value type (#443) is an addition,
so it can come in a 1.x minor; it moves to v0.51.0.
