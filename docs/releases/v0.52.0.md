# v0.52.0

**The terraform-file reading joins the registry line.** From `v0.52.0`, `jpack terraform facts`,
its batch lines, the `TF-*` codes and the format table are part of the registry line under the
promise in [VERSIONING.md](../../VERSIONING.md#the-terraform-file-reading). This is the release
that section's "from the release that names it so in its release notes" refers to. `jpack` and the
runtime module stay `0.x`.

The reading follows the terraform-file companion's first release, spec tag
`terraform-file-v1.0.0` (`spec/terraform-file.md`, reading `1.0.0`), which is published as
released and not yet stable. No byte `jpack terraform facts` writes, and no code it reports,
changes in this release.

## The terraform-file reading is part of the registry line

- **What it is.** The commands `jpack terraform` and `jpack terraform facts`, with the flags
  `--plan`, `--state`, `--type`, `--mode`, `--address`, `--actions`, `--max` and `--max-bytes`,
  their forms, defaults and exit codes; the reading of the companion's §§2 to 9 at
  `terraform-file-v1.0.0`; the eight refusal codes `TF-SIZE`, `TF-JSON`, `TF-FORMAT`,
  `TF-DOCUMENT`, `TF-SENSITIVITY`, `TF-SELECT-BOUND`, `TF-NUMBER` and `TF-VALUE-LIMIT`, each an
  error; the accepted `format_version` table, release `1.0.0` (plan `1.0`, `1.1` and `1.2`; state
  `1.0`); the batch lines as their bytes; a refusal's diagnostic on standard error; and the bounds.
- **The promise.** The registry line's rules apply: within major version 1 of the line, nothing is
  removed, no bound is tightened, and a new refusal code, or a refusal of a file that was read
  before, is a breaking change. The batch lines have no selector of their own, so a change to their
  bytes for the same file and the same flags is a breaking change.
- **A new table row.** The companion adds an accepted `format_version` as a patch release of its
  table. This runtime adopts a new row in a minor release, and that release's notes name the table
  release it implements.
- **An erratum release.** A companion release that corrects the text or the vectors and adds no
  row is adopted as VERSIONING.md's "An erratum release" states.
- **Released, not stable.** The companion becomes stable when a second, independently written
  reader agrees on every vector (its §12). That changes nothing in this promise.
- **Not part of it.** The wording of messages; the Go package and its acquisition record, which no
  command writes; the `terraform-file` kind in a dialect document, which waits on dialect version
  3; Terraform's outputs, `format_version` values `0.x`, and other tools that write the same JSON;
  memory use and time.

## What is new

- **The companion's vectors run in the tests, pinned to the release tag.** The 206 hand-written
  vectors of `terraform-file-v1.0.0` are vendored unmodified under
  `internal/terraformfile/testdata`, pinned to the tag's commit and by each file's SHA-256. The
  159 read rows run through the reader, the 10 batch rows through `jpack terraform facts`, and 21
  of the 37 malformed declarations through its flags, each an unusable command line (exit 3); the
  other 16 have no command-line form and are not run. Every row run gives its one expected result.
- **The format table is release `1.0.0`.** The acquisition record's `formatTable` is `1.0.0`; it
  was `proposed-1`, this runtime's provisional name. No command writes the record.
- **What VERSIONING.md promises for the reading** (VERSIONING.md, "The terraform-file reading"):
  the command, its flags and exit codes, the codes, the table, the batch lines and the bounds, the
  rule for a new table row, and the rule for an erratum release. SECURITY.md names `jpack
  terraform facts` in the registry line's support window.
- **The fuzz workflow takes a fuzzing time on demand.** A manual run of
  `.github/workflows/fuzz.yml` accepts `fuzztime` (default `30s`, at most `340m`), and each
  target's job limit follows it. The scheduled run still fuzzes each target for 30 seconds.
- **The start-up module's refusals and limits are in the mutation table**
  (docs/registry-mutation-table.md): 24 rows, one for each function that uses an exported error
  value or limit, each with the test that kills its recorded mutant. No exported identifier,
  message or behaviour of the module changes.

## Changes a caller may notice

- **The `TF-*` codes may be branched on.** They were provisional; they are now the released
  companion's, under the promise above.
- **The help of `jpack terraform`** names the companion's release instead of calling it proposed.

## Known limits

- **An interrupt on the last environment.** When the last environment's emitter leader exits 0
  and an interrupt then cuts a group member's response, the run can report `EMIT-RESPONSE`, not
  `EMIT-INTERRUPTED`. It is still a failure. This is #478.
- **The emitter is not sandboxed.** It is code the repository chose to run, with the user's
  rights, bounded by its environment, its time limit and its output.
- **Declarations with no command-line form.** Sixteen of the companion's malformed declarations
  (one that is not an object, an unknown member, another document, a member of another JSON type)
  cannot be written as flags, so `jpack terraform facts` cannot be checked against them.
