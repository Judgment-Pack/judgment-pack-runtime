# v0.51.0

**This release names the registry line stable.** From `v0.51.0`, the registry line is stable under
the promise in [VERSIONING.md](../../VERSIONING.md#the-registry-line), and its support window
applies. The start-up module is tagged `startup/v1.0.0` with this release, on the same commit as
`v0.51.0`, so the start-up module's 1.0 promise and the line's start together. `jpack` and the
runtime module stay `0.x`.

The line follows the registry companion's first release, spec tag `registry-v1.0.0`, which is
published as released and not yet stable. `jpack terraform facts`, the `TF-*` codes and the
`proposed-1` table stay provisional and outside the line's 1.0 promise: no spec release carries
dialect §4.5 yet.

The release also stops reading a git index with an offset table, reports an interrupt that comes
after `jpack emit --check`'s last emitter, and corrects what SECURITY.md and VERSIONING.md say
about the commands that run emitters.

## The registry line is stable

- **What the line is.** The commands `jpack registry` (all of its subcommands), `jpack emit` and
  `jpack emit conformance`, with their flags and exit codes; the formats they read and write, each
  under its selector; their diagnostic codes and bounds; the reference emitters' manifests, the
  kinds they read and their options; and the start-up module.
- **The promise.** Within major version 1 of the line, nothing is removed, no bound is tightened,
  and no code, member or rule changes meaning. A format gains a member only under a new minor
  selector. A new command, flag or warning code may come in a minor release; a new refusal of
  input that was accepted before is a breaking change. A deprecated part keeps working for the
  rest of major version 1. A format of the line with no selector of its own is promised as its
  bytes.
- **The exceptions.** A security fix may refuse input that was accepted before, in a patch
  release, when nothing narrower closes it. A conformance fix may refuse input that the released
  companion text forbids. The release notes name either, with the refusal code and the input.
- **Support.** Fixes land in the latest `jpack` minor and the latest `startup/v1` tag. Security
  fixes are also backported to the previous `jpack` minor and the previous `startup/v1` minor for
  three months after its successor is released. There is no service-level guarantee.
- **The codes are the companion's.** Every `REG-*`, `FACTS-*` and `EMIT-*` code this runtime
  reports is named in `registry-v1.0.0`'s code list, under its name and severity, and is no longer
  provisional. No code, severity, message or behaviour changes in this release.
- **Released, not stable.** The companion becomes stable later, when a second, independently
  written reader agrees on its rows (its §15). That changes nothing in this promise.
- **`startup/v1.0.0`** carries the start-up changes made on the main branch since
  `startup/v0.1.0`: `ReadFile` refuses a file others may write under every rule
  (`ErrWorldWritable`), `ReadFile` and `ReadResolvedFile` refuse a named pipe without waiting on
  it, and `ErrNotRegular`'s text no longer says "secret file". From this tag, within major
  version 1, no exported identifier is removed or changes meaning, and no bound is lowered.
- **Not part of the line.**
  - `jpack terraform facts`, the `terraform-file` reader, its batch lines, the `TF-*` codes and
    the `proposed-1` table. A later release may change them, naming the change in its release
    notes. `FACTS-ID-LIMIT`, which the command also reports, is the registry companion's.
  - An emitter's own `x-` diagnostic codes.
  - The code the reference emitters generate, and their first-version scope:
    `jpack-emit-go-facts`' refusal of open objects, `anyOf` and objects that mix named members
    with a `*` member may be lifted in 1.x.
  - The wording of messages, the order of diagnostics that share a location, and the timing of
    runs.

## What is new

- **An index with an offset table is not read** (ADR-0099).
  - `jpack emit conformance` passed over the index's `IEOT` and `EOIE` extensions and read the
    entries in order. Git with several index threads reads them in blocks at the offset table's
    offsets, so a hand-made index whose table disagreed with its entries was read differently by
    git and by the harness. A link git tracks could then be left out of the repository copy with
    `EMIT-LINK-OMITTED`.
  - An index holding either extension is now not read, as an index git wrote without its checksum
    is not. Every link that leads out of the repository is then refused with
    `EMIT-HARNESS-BOUND`, as before v0.50.0.
  - Git writes both only when `index.threads` is set to other than 1, or
    `index.recordOffsetTable` or `index.recordEndOfIndexEntries` is on.
- **`jpack emit --check` reports an interrupt after the last emitter** (ADR-0098). An interrupt or
  SIGTERM that came once the last environment's emitter had ended, during the scan of the owned
  paths or the comparison, is now refused with `EMIT-INTERRUPTED` at `/command`, as `jpack emit`
  is before its write. ADR-0098 also states that an interrupt once the write has begun leaves the
  outcome `written`, exit 0.
- **Who owns each registry-line code** (VERSIONING.md). The registry companion's code list names
  every `REG-*` code this runtime reports, the `FACTS-*` limit, form and order codes,
  `FACTS-ID-LIMIT`, `EMIT-MANIFEST`, and the thirteen host and harness codes this runtime reported
  as its own. The dialect companion names `TF-VALUE-LIMIT` with the other `TF-*` codes, makes
  `terraform-file` a proposed kind of dialect version 3, and takes `proposed-1` as its first
  table. VERSIONING.md now pins `registry-v1.0.0`.
- **SECURITY.md and VERSIONING.md say what the registry line does.**
  - SECURITY.md said the runtime invokes no subprocess and writes in exactly three ways. It now
    names the two places that start another program, `jpack emit` and `jpack emit conformance`
    (the emitter) and `jpack experimental check-published` (`git`), and the five places the
    runtime writes, among them the paths an emitter manifest owns, a vector's `expected/` under
    `--update`, and the system's temporary directory.
  - VERSIONING.md's list of what the line is now names the reference emitters, as far as the
    registry companion's §11.6 promises them: each one's manifest, the kinds it reads and its
    options, not the bytes it writes.
  - SECURITY.md points to the registry line's support window.

## Changes a caller may notice

- **The registry line's codes may be branched on.** They were provisional; they are now the
  released companion's, under the promise above.
- **An index with an offset table.** A repository whose index holds `IEOT` or `EOIE`, and that
  holds an untracked outward link, ran under v0.50.0 with `EMIT-LINK-OMITTED`. It is now refused
  with `EMIT-HARNESS-BOUND`.
- **`jpack emit --check` interrupted after its last emitter** is refused with `EMIT-INTERRUPTED`,
  where v0.50.0 exited 0 or 1 as if no signal had come.

## Known limits

- **An interrupt on the last environment.** When the last environment's emitter leader exits 0
  and an interrupt then cuts a group member's response, the run can report `EMIT-RESPONSE`, not
  `EMIT-INTERRUPTED`. It is still a failure. This is #478.
- **An interrupt once the write has begun.** `jpack emit` finishes the write and reports the files
  written, with exit 0, as ADR-0098 states.
- **An emitter that leaves its process group.** When the interrupt cannot reach it through its
  group, the run is reported `EMIT-PROCESS`, still a failure.
- **On Windows,** an interrupt at kill time may report `EMIT-INTERRUPTED` for an emitter that was
  already failing with exit 1.
- **Descriptors.** A descriptor above the scan's top is still missed: one opened before the hard
  limit was lowered below it, or one above 65536 where the hard limit is higher.
- **The emitter is not sandboxed.** It is code the repository chose to run, with the user's
  rights, bounded by its environment, its time limit and its output. The harness's repository
  copy keeps an honest emitter's mistakes out of the repository, not a hostile one's.
