# v0.42.0

This release adds an experimental description of a loaded pack, for review by people and by
tools: `sdk.Pack.View` and `sdk.Pack.Identity` in the Go API, and `jpack packs describe` on the
command line.

## Changes for hosts upgrading from `v0.41.0`

- **Nothing changes for an existing project or host.** No command, output, configuration or
  persisted format that `v0.41.0` had is changed. Everything added is EXPERIMENTAL.

## Describing a pack

`sdk.Pack.View` returns the whole of an admitted pack as a `view.PackView` of the new package
`sdk/view` (#372, ADR-0074), and `sdk.Pack.Identity` returns the pack's id, version,
`specVersion`, profile as stated, and the `sha256:` digest of the exact bytes loaded.

- **Complete or refused.** The view carries every member as written: an absent member is
  absent, an empty one is empty, rules keep document order, and numbers are written exactly as
  the document writes them. `View` returns an error for any member it does not read; it never
  returns a partial view. It never evaluates.
- **Two encodings.** `PackView.JSON` writes canonical JSON (`digest`, `pack`, `viewVersion`);
  `PackView.Markdown` writes a Markdown rendering. Both carry `viewVersion` `"1"`;
  [VERSIONING.md](../../VERSIONING.md) states when it moves.
- **Pack text is data.** The Markdown escapes every pack string, and shows control, format and
  line-separator characters as code points. In the positions the evaluator matches on (fact
  paths, fact values, extension names and values), a string with any character outside
  printable ASCII is also written in ASCII-escaped form, so two strings that differ never read
  alike there.
- **What escaping does not stop.** A GFM reader still links an email address, and a forge links
  mentions, issue references and commit ids. Post the Markdown as a file, or inside a fenced
  block longer than any backtick run in it. Free text (titles, descriptions, rationales) is not
  marked for look-alike or invisible characters; compare the JSON where that matters.
- **Describing is not evaluating.** A pack that requires an extension this runtime does not
  support is still described. An absent `profile` is shown as absent; the evaluator applies the
  default.

`jpack packs describe <pack-or-> [--format markdown|json]` writes the same bytes for one local
pack or standard input. Markdown is the default; `--format json` carries the canonical JSON as
the `view` string of the standard envelope. It reads no project configuration. A pack the
loader refuses is reported with the loader's code and the exit code `experimental evaluate`
gives.

[docs/building-with-packs.md](../building-with-packs.md) "Review" states the format and the
escaping rule.

## Not in this release

Labels on rules and outcomes, named value sets, and filtering a view by label are proposed for
the specification (RFC 0031, a draft) and are not part of any admitted `specVersion`. A pack
that uses them is refused.

## Decisions

ADR-0074 is accepted with this release. Its clean-room review is recorded on #373 (a Claude
Opus review of a Claude Opus build; not a cross-vendor claim).
