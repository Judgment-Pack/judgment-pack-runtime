# v0.47.0

This release adds a reader for registries of adopter-declared kinds: `jpack registry validate`,
`resolve`, `import`, `facts` and `check-pack`. It also adds an outcome gate on `experimental
evaluate` for CI, and the fixes from the v0.46.0 release review to `experimental check-published`.

## For an unchanged pack

For every supported `specVersion` (`0.5.0`, `0.3.0`, `0.2.0-draft`, `0.1.0-draft`), no
disposition, evaluation output, decision record byte or digest differs from `v0.45.0`. Comparing the
two release binaries:

- **Conformance runs.** `spec test-conformance --format json` gave the same bytes, apart from the
  tool's version, for each selector, with and without `--strict`.
- **The evaluation corpora.** `experimental evaluate-corpus --format json` gave the same bytes
  for `0.2.0-draft`, `0.3.0` and `0.5.0` (20, 20 and 103 cases).
- **Spec validation.** `spec validate` on each of the 2709 JSON documents of Spec `v0.6.0` gave
  the same exit code and the same output.

The exceptions are in two experimental commands:

1. **`experimental evaluate --require-outcome`** is new. Without the option, every exit code and
   every byte of output is what it was.
2. **`experimental check-published`** (#418) changes in three ways:
   - A document whose `id` or `version` is longer than 4096 bytes is reported as unreadable.
   - A manifest that declares another `manifestVersion` gets the version refusal (exit 2), even
     when it also adds a member. Before, that manifest got exit 1.
   - With `--format json`, a path or tag ref that is not UTF-8 gains a `pathEscaped`, `refEscaped`
     or `firstTagEscaped` member. For UTF-8 names the output is the same bytes, and
     `publishedCheckVersion` stays `"1"`.

## What is new

- **`jpack registry validate|resolve`** (ADR-0093) reads a registry of entries of adopter-declared
  kinds, per spec RFCs 0034 and 0035.
  - `validate` runs the eight steps and writes a report of codes, fixed messages and locations,
    never a value. The report is capped at 1000 diagnostics with `REG-REPORT-TRUNCATED`.
  - `resolve --environment E` writes one environment's resolved document as RFC 8785 JSON.
  - Nothing is fetched. A secret reference is checked for form and left as written.
- **`jpack registry import`** (ADR-0094) converts the registry's YAML authoring subset to canonical
  JSON. It refuses everything outside the subset and never coerces a value.
- **`jpack registry facts` and `jpack registry check-pack`** (ADR-0095; spec RFC 0037 §1 to §5).
  - `facts` writes registry entries as batch lines that `experimental evaluate --batch
    --require-outcome` reads, and can write the kind's generated facts contract.
  - `check-pack` reports, without evaluating, where a pack's fact pointers and comparisons don't
    fit a contract.
- **Registry bounds.** Every input within the size bounds now costs about what its size does. The
  bounds cover:
  - schema expansion, 4096 subschemas, with each `$ref` counted as the definition it names;
  - compiled patterns, 4096 instructions per pattern and 65,536 per kind;
  - distinct-item checks, a nesting depth of 32 on the resolved document, and number literals;
  - a shared validation work bound of 2^26 node visits across environments.

  A value shared by many environments is checked and measured once (#432, #434).
- **An outcome gate on `experimental evaluate`** (ADR-0092; EXPERIMENTAL). `--require-outcome a,b`
  exits 0 when every item's disposition is a listed outcome, 1 on a finding, and 2 when the gate
  could not judge. `--gate-summary FILE` writes a JSON summary that carries no fact value.
- **`experimental check-published`** carries the v0.46.0 release review's fixes (#418). The work
  per identity no longer grows with its digests, git output is bounded, no grafts or
  commit-graph file is read, and the escaped names above are added. The two known limits
  stated in v0.46.0's notes are fixed.

The `REG-*`, `REG-YAML-*` and `FACTS-*` codes are provisional until the registry companion is
released (VERSIONING.md). The typed builders of RFC 0037 §6 are not built.

## Compatibility

| With | Version | Notes |
|---|---|---|
| Specification | Spec `v0.5.0` to `v0.5.2` (Core `0.5.0`, `0.3.0`, `0.2.0-draft`, `0.1.0-draft`) | Core `0.6.0` (Spec `v0.6.0`) is not read by this release. `0.3.0` stays the default selector. Only the `base` profile of `0.5.0` is read. |
| Registries | spec RFCs 0034, 0035 and 0037 §1 to §5 | The registry companion is not yet released; its codes are provisional. |
| Dialect documents | format version `3` | Dialect formats `4.0.0` and `4.1.0` are not read by this release. |
| Decision records | `recordVersion` `1.0.0` (plain) and `2.0.0` (keyed) | Unchanged from `v0.46.0`. |
| Runner | `v0.31.0` and later | Nothing in this release changes what a Runner reads from the Runtime. |
| Gateway | any | The Runtime does not call the gateway. |
| Audit trails and lock files | written by any earlier release | Read unchanged. |

## Decisions

ADR-0092 to ADR-0095 were accepted on merge. The release review (#432; same vendor, not a
cross-vendor claim) asked for its findings to be fixed before the tag. They are fixed in #433, and
the per-environment cost it led to (#434) is fixed in #435.
