# v0.43.0

This release lets a pack carry annotations and value sets, EXPERIMENTALLY, under the staged draft
selector `0.4.0-draft`, and lets the pack description show them and be filtered by annotation.

## Changes for hosts upgrading from `v0.42.0`

- **Nothing changes for an existing pack, project or host.** A pack under `0.3.0` or
  `0.2.0-draft` is validated, evaluated and described exactly as `v0.42.0` did it, and `0.3.0`
  stays the default selector. Everything added is EXPERIMENTAL.
- **Runtime discovery lists one more selector.** `jpack version`, `describe` and the MCP runtime
  description now list `0.4.0-draft`. Its evaluator entry carries `stage: "staged-unreleased"`;
  the plain list of supported selectors has no stage marker, so read the evaluator entry before
  treating a listed selector as released.

## What `0.4.0-draft` is

`0.4.0-draft` is a working selector that a specification commit stages for RFC 0031, which is a
draft (#376, ADR-0075). No specification release carries it, and **the specification may rename
or change it**; a pack written to it may need its `specVersion` edited later. This runtime makes
no conformance claim for it. The bundle is vendored from specification commit
`4cae6a34058883955cf3b00a4c9672e2c8ad7975`, and its lock says `stage: staged-unreleased`. Only the
`base` profile is admitted.

A pack that declares `"specVersion": "0.4.0-draft"` may carry:

- **Annotations.** Under the reserved extension `org.judgmentpack.annotations`, on the pack, an
  outcome, a rule and a value-set entry: 1 to 16 keys, each value a string or a list of strings.
  Annotations never change a decision.
- **Value sets.** A root `valueSets` member holds named sets of values. A fact `in` condition
  names one with `valueSet` in place of an inline `value` list, and is evaluated exactly as if it
  listed the set's values. A reference to a set the pack does not define is refused
  (`JPS-SEMANTIC-UNRESOLVED-VALUE-SET`).

The pack's identity and digest stay over the exact bytes loaded.

## Where it is read, and where it is refused

- **Read:** validation, `spec test-conformance --spec-version 0.4.0-draft`, the evaluator, and
  every surface that reaches the evaluator except graph evaluation: `experimental
  evaluate-corpus`, the project walk, fact advice, matrix validation, coverage, the examples and
  the pack description.
- **Refused:** graph evaluation, the dialect check and the policy check refuse a `0.4.0-draft`
  pack with `JPS-STAGED-DRAFT-UNSUPPORTED`. Pack-design analysis reports `pack-unsupported`, and
  an MCP tool's standalone `spec_version` does not accept the selector.
- **Rules-overlap advice.** `JPS-RULES-OVERLAP` is reported as before, but offers no exclusive
  rewrite for a pair where either condition names a value set, because the rewrite would drop
  the reference.
- **Staged runs say so.** A run of the staged cases or rows reports `staged` and no suite
  version, and one row the specification holds is reported as held, not passed.

## Describing and filtering

- **The description shows them.** `sdk.Pack.View` and `jpack packs describe` show a
  `0.4.0-draft` pack's value sets and annotations as typed fields, in Markdown and in JSON. A
  reference is shown as the set's id and is never expanded. `viewVersion` stays `"1"`: no pack
  an earlier release could describe is shown differently.
- **Filter by annotation.** `jpack packs describe --filter key=value` (repeatable) and
  `sdk.Pack.FilteredView` show only the outcomes and rules whose annotations match every
  criterion. A value matches a string, or a list that holds it, compared by exact code point.
- **A filtered view is not the pack.** It says so, carries `filteredViewVersion` `"1"` and no
  `pack` member, and states the filter, the matched and total counts, the position of each match
  and the pack's full identity. With `--format json` the bytes are the envelope's `filteredView`
  member, with `status` `"filtered"`.
- **Refusals.** A criterion no annotation could hold, and a pack under any other `specVersion`,
  are refused (`JPS-INVOCATION-FILTER` on the command line) rather than shown as no matches.

[docs/building-with-packs.md](../building-with-packs.md) "Review" describes the view and the
filter.

## For maintainers

`tools/sync-spec-artifacts --staged <selector>` imports a staged selector from one exact commit
of a clean checkout, and `--replace` refreshes only a staged bundle of the same selector
([docs/releasing.md](../releasing.md), "Refresh a staged draft selector").

## Decisions

ADR-0075 is accepted with this release, including the decision it left to the release: this
release ships the staged selector. Its clean-room review is recorded on #377 (a Claude Opus
review of a Claude Opus build; not a cross-vendor claim).
