# v0.41.0

This release adds an experimental in-process Go API, package `sdk`; a command that answers
whether a reviewed-set lock covers a document without opening a project; and a way for a
project to require that its decision records are signed.

## Changes for hosts upgrading from `v0.40.0`

- **A reviewed-set lock with a member the reader does not know is refused.** The lock reader
  refuses an unknown member, including case and Unicode-fold variants of the known names, with
  `JPS-LOCK-SHAPE` (exit 1), wherever the lock is read: `packs verify`, `packs covers` and the
  deciding surfaces' check. Every lock `packs lock` wrote still reads. A lock that was edited by
  hand or written by another tool with extra members is now refused: write it again with
  `packs lock`.
- **A deciding run may report one new warning.** When a project names a signing key that will
  not sign the run's record, `experimental evaluate`, `experimental graph evaluate` and the MCP
  `experimental_evaluate` tool still decide and record, unsigned, as before, and now report one
  `JPS-AUDIT-UNSIGNED` warning (#354, ADR-0071): in a new `diagnostics` member of the payload
  under `--format json` and over MCP, and as a `warning:` line on standard error otherwise. The
  disposition, the record and the exit code are unchanged. A host that reads the JSON payload
  strictly must accept the new member; a host that treats any standard-error output as a
  failure must not.
- **Nothing else changes for an existing project.** Configurations under configVersion `"1"` to
  `"7"` read as before. Persisted audit lines and their digests are unchanged.

## Package `sdk`: evaluate in-process from a Go program

Package `sdk` is an experimental in-process Go API over the shared evaluator (#368, ADR-0073).

- `sdk.Load` validates a pack from bytes and admits it once, under the contract the pack
  declares and the caller's supported extensions. A loaded pack is immutable, safe for
  concurrent use and never validated again.
- `Pack.Evaluate` takes a facts document and an optional evidence document and returns the
  §8.3 disposition as typed values and as its canonical bytes. `Evaluation.JSON` returns the
  `experimental evaluate --format json` envelope with `command` set to `sdk evaluate`.
- A refusal of the caller's input is a `*sdk.Refusal` with the §8.4 class and phase and the
  CLI's code and message, plus the `spec validate` diagnostics for a pack that failed
  validation. A fault of the runtime wraps `sdk.ErrInternal`. A done context is returned as the
  context's own error.
- `sdk.Describe` reports the bundled specification versions, the evaluator contracts and the
  bundled evaluation corpus's `suiteVersion` for each, so a program can check at startup that
  it runs the version it pinned.
- The package reads no project, file, environment variable or network. The context is checked
  when a call starts; a started evaluation is not interrupted by it, and the documented limits
  bound it.

The package is experimental: [VERSIONING.md](../../VERSIONING.md) says what a tagged release
promises for it, and the package documentation lists every exported identifier.
[CONFORMANCE.md](../../CONFORMANCE.md) names `sdk.Pack.Evaluate` among the surfaces that reach
the evaluator, which are now eleven, and states the conformance claim in full. The bundled
evaluation corpora run through the public API in the test suite.

## `jpack packs covers`

`jpack packs covers --lock FILE --id ID --pack FILE` answers whether a reviewed-set lock covers
a pack's exact bytes without opening a project (#364, ADR-0072); `--graph-id` and `--graph` ask
the same of a graph. It exits 0 when the lock's entry agrees with the SHA-256 of the file's
bytes and 1 with `document-drift` or `lock-entry-missing` when it does not. With `--config` it
also names `config-drift`, `path-mismatch` and `locked-but-undeclared` for that id. It
evaluates, writes and records nothing, and never reads standard input. A lock, document or
configuration it cannot read, or one past its limit, is refused with exit 4 and never reported
as not covered.

## Requiring signed records

configVersion `"8"` adds the audit member's `requireSigning` (#354, ADR-0071). When true:

- the deciding surfaces refuse, before evaluating and with nothing recorded, a run whose named
  key would not sign and every run while no key is named (`JPS-AUDIT-SIGNING-REQUIRED`, exit 1);
- at the write, under the trail's lock, a run whose key is no longer the key in force, or whose
  trail no lock can be taken on, fails with nothing appended;
- a run whose signature cannot be written fails with its record written, unsigned, and a
  message saying so (`JPS-AUDIT-WRITE`, exit 4).

A declared rehearsal is not refused.
